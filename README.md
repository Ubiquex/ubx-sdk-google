# ubx-sdk-google

Typed bindings for Google Cloud (`[dynamic_provider_groups.google_all]`,
Discovery-Doc-sourced via `ubx-provider-dynamic`), generated by
[ubx](https://github.com/ubiquex/ubiquex) (`ubx sdk gen`), for all three
SDK languages in one combined repo:

- [`sdk/go/`](sdk/go/) — Go bindings, module `github.com/ubiquex/ubx-sdk-google/sdk/go`
  (a subdirectory Go module, tagged `sdk/go/vX.Y.Z`)
- [`sdk/typescript/`](sdk/typescript/) — TypeScript bindings, published to JSR as
  [`@ubx/sdk-google`](https://jsr.io/@ubx/sdk-google)
- [`sdk/python/`](sdk/python/) — Python bindings, published to PyPI as
  [`ubx-sdk-google`](https://pypi.org/project/ubx-sdk-google/) (imported as
  `ubx.google.*`, a real PEP 420 namespace package)

One package per Google Cloud service boundary (`compute/`, `storage/`,
`dataflow/`, `bigquery/`, ...), one file per resource type, in every
language.

## Install

```
go get github.com/ubiquex/ubx-sdk-google/sdk/go
npm install @ubx/sdk-google
pip install ubx-sdk-google
```

## v1.0.0: source change AND scope expansion, not just a version bump

Every version before `1.0.0` was generated from the `hashicorp/google`
Terraform provider (1333 types, itself mostly Compute-domain-shaped). As
of `1.0.0`, this repo is generated from Google's own real Discovery
Documents, the source `ubx` actually resolves and applies changes
against today — and from ALL 162 of them (every real GCP product with a
live Discovery Doc, not just Compute), not one. 880 real resource types
across every service boundary GCP publishes a Discovery Doc for, merged
into this one repo by `ubx sdk gen`'s own new
`[dynamic_provider_groups.<name>]` mechanism (`ubiquex` commits
`c55908c`/`8062883`) — the real fix for a gap this pipeline's own config
comments had named and deferred since the Discovery Doc corpus was
first expanded past Compute alone.

The old `hashicorp/google`-shaped identifiers are gone. Checked overlap
against just the Compute-domain subset (95 of the 880 real resources)
is 81/95 (85.3%) — real, confirmed, the same figure this project's own
prior measurements already found for that narrower scope — but against
the full 880-resource corpus it's only 81/880 (9.2%), and even within
that 81-resource overlap real field drift exists (`deletion_policy` is
a Terraform-only synthetic field absent from the real Discovery Doc;
`status`/`purpose`/`self_link`/`kind` are Discovery-Doc-only). This is a
genuine source change plus a real scope expansion, not a compatible
superset — hence `1.0.0`, not a minor bump.

`VERSION` records a `merged-schema-sha256`: a SHA-256 of the combined,
deterministic post-enrichment IR (`ubx sdk gen --dump-ir`'s own
`schema.json` shape) covering all 162 members at once, plus the member
count and fetch date. There is no single upstream "GCP version" the way
`hashicorp/google@X.Y.Z` was one string — 162 independent Discovery Docs,
each its own live, unversioned endpoint — so a single merged-content
hash is the real, honest equivalent of the content-hash scheme
`ubx-sdk-aws`/`ubx-sdk-kubernetes`/`ubx-sdk-datadog`/`ubx-sdk-github`
already use for their own no-discrete-release sources.

`.github/workflows/version-watch.yml` (polled the Terraform Registry for
a `hashicorp/google` bump) no longer matches this repo's real source at
all and needs its own replacement — a real, 162-member content-hash
watch is separate follow-up work, not done in this PR; the workflow is
removed here rather than left silently watching a source this repo no
longer generates from.

Package identity (module path, JSR/PyPI names) is unchanged — only
the generated content and `VERSION`'s own format changed.

Local sanity: `go build`/`go vet` clean against the regenerated
`sdk/go/` tree (1042 files, 162 real service packages). TS/Python
sanity (`deno check`, real module import) not run locally.

Depends on the shared runtime: [ubx-sdk-go](https://github.com/ubiquex/ubx-sdk-go) (Go),
[`jsr:@ubx/sdk`](https://jsr.io/@ubx/sdk) (TypeScript),
[`ubx-sdk`](https://pypi.org/project/ubx-sdk/) (Python, imported as `ubx_sdk`).
